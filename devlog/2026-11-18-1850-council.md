# Add a Council Skill With a Provider Ladder

The `council` skill seats independent reviewers from as many model providers
as the host can reach. Issue #388 carries the contract, including the
findings and scoring interfaces that #390 (hill-climb) and #391 (pre-push
review) will call. The skill draws on tstack's `council` and on Theo's report
that repeat scoring runs disagree and that showing judges the target inflated
scores.

## Decisions

- **Chose a ladder over tstack's fixed three providers.** tstack asks one
  model from each of three providers and reports when it can't reach them. The
  owner uses only Claude and Codex, and some hosts reach one provider or none.
  A ladder (one model per reachable provider, then two fresh contexts on one
  provider, then no council) gives each host its strongest panel and names the
  rung, so the report says how independent the review was.
- **Chose the other provider's member first over launching the panel at
  once.** Each member is a high-effort run. The member least likely to share
  the lead's blind spots finds the most per run, and a confirmed blocker from
  it means the change will be revised anyway, so further members would review
  a version that won't ship. Risk-class work seats the full panel regardless,
  since a second view there is worth the run.
- **Chose scores that never gate a review over a pass or fail threshold.**
  Repeat runs of one judge give different scores, so a single score is noisy.
  Council reports both scores and their spread and leaves the meaning to the
  caller, which can weigh the spread. A threshold would hide that noise.
- **Chose an empty seat over substituting a model.** A user who names a member
  wants that model's view. A silent substitute reports a panel that didn't
  run, which defeats the report's purpose of stating independence.
- **Chose a full panel in scoring mode over staging it.** Disagreement between members, which
  the per-member scores show, is part of a scoring result, and staging depends on blockers, which
  scoring doesn't produce.

Revisit when the owner adds a third provider, when a caller needs council to
return a verdict, or when repeat scores prove stable enough that two runs per
member waste a run.
