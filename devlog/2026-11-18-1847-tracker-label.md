# Label Every Tracker for People, Not for Skills

The shared tracker format now asks every tracker, whether wave, feature, or
backlog, to carry the `tracker` label, and agent-setup's audit offers to
create it. Issue #396 carries the contract.

## Decisions

- **Chose a label for people over a label lookup by skills.** The label lets
  the owner and agents list a project's trackers on the forge. Skills keep
  reading only the trackers that the project's records and the owner's
  requests name. This keeps three rules unchanged: `plan-work-unit`'s "Do not search
  the forge for trackers beyond those records", merge-cleanup's "Do not
  search for or infer additional containers"
  (`skills/merge-cleanup/references/project-obligations.md`), and
  `plan-and-handle-batch` taking the tracker the request names. A label search
  would find trackers that no record names, including stale ones and ones not
  in the shared format. A tracker kept in a comment can't carry the label at
  all.
- **Corrected the format's claim of a lookup.** The old §title sentence said
  tooling finds a wave tracker by its milestone and the `tracker` label. No
  tooling did that. The format now says no tooling selects a tracker by label
  or title text.
- **Chose a fixed color, `fbca04`.** This is the owner's choice from
  2026-11-18. The audit's default description reuses the one already on
  free-skills' label: "Coordination issue in the shared tracker format; lists
  work units, not work itself".
- **Kept the audit to creating the label.** It never applies the label to an
  issue and doesn't search for unlabeled trackers. Labeling trackers stays the
  owner's job.

Revisit when a skill needs to find trackers that no record or request names.
