# Run Markdown and script checks on every pull request

Issue [#190](https://github.com/freeasinbird/free-skills/issues/190) adds the
first general Markdown workflow. The workflow makes the repository's existing
local checks visible and enforceable on every pull request.

## Decisions

- **Run all script test matrices on every pull request.** The managed-sync
  matrix had gone red after canonical prose changed without touching its test
  script. Change-based filters would repeat that blind spot. A 14-way matrix
  keeps each result visible and makes wall time track the slowest script,
  rather than the roughly 22-minute measured serial total.
- **Keep the fast checks in one job with named steps.** Markdown lint,
  formatting, prose-tics, skill structure, and managed sync each get a clear
  status while sharing one checkout.
- **Pin the two npx tools in CI.** CI uses `markdownlint-cli2@0.23.2` and
  `prettier@3.9.6`, the versions verified for this work. Local commands stay
  unpinned for convenience. The pins stop an upstream release from breaking
  an unrelated pull request.
- **Install only the runner dependency that a matrix needs.** The
  merge-cleanup orchestration matrix requires `rg`, which is not present on
  the current GitHub-hosted runner. Its job installs ripgrep before the test;
  the other matrix jobs avoid that setup cost.
- **Publish a unique fast-check context.** The Markdown workflow uses
  `markdown-checks`, not the commit-message workflow's `check`, so repository
  protection can require both without an ambiguous context name.
- **Treat temporary Chrome profile removal as best-effort cleanup.** CI wrote
  the requested PNGs, then failed while a Chrome descendant was still writing
  to its temporary profile. Removal keeps bounded retries, but a final failure
  now warns without changing a successful capture's exit status.

## Refute-First Findings

- **Confirmed:** Immediate profile removal can race Chrome descendants. The CI
  log wrote both requested PNGs before `fs.rmSync` raised `ENOTEMPTY` inside
  the profile's `Default` directory.
- **Disproved:** Clip geometry and device-pixel-ratio handling did not cause
  the failure. The earlier `0x0` result was the smoke's sentinel for any
  nonzero capture exit; the diagnostic run located the failure in cleanup.
- **Rejected:** Skipping the live smoke or retrying the whole capture would
  weaken the new CI gate. The regression case instead injects only profile
  removal failure after a successful write, then requires the PNG, exit zero,
  and the scoped warning.
- **Disproved:** The change cannot redirect deletion to another path. The
  profile value comes only from `mkdtempSync` and reaches `rmSync` unchanged;
  the patch adds no unbounded loop or cross-platform-only state check.
- **Allowed limitation:** A longer-lived Chrome descendant can leave a
  temporary profile behind after the bounded retries. The warning exposes that
  residue, while capture, validation, and PNG-write failures still fail.

## Rejected Alternatives

- **Run matrices only when their matching scripts change:** rejected because
  fixtures can depend on other files. The stale managed-sync fixtures proved
  that a dependency change can break a matrix without changing its script.
- **Run matrices in one serial job:** rejected because the measured scripts
  range from a few seconds to more than seven minutes. Separate jobs shorten
  feedback and show every failure even when another matrix is red.
- **Use floating npx package versions:** rejected because reproducible CI is
  worth the small maintenance cost of intentional upgrades.

Revisit when GitHub-hosted runner limits make 14 parallel jobs impractical,
or when the repository adopts a dependency lockfile for its Markdown tools.
