# Recording the forge slug for aliased remotes

The 2026-09-01 transcript audit found 85 freeside sessions calling `gh`
against `freeasinbird/freeside`, a repository that doesn't exist; the real
slug is `freeside-ai/freeside`. Its origin, `git@bnw.github.com:...`, uses
an SSH host alias, and freeside's AGENTS.md never states the slug. Issue #209
set the contract: agent-setup records the forge host and slug outside the
managed blocks, and await-pr-review and merge-cleanup read that record before
inferring a repository from a remote.

## Decisions

- **The record lives in the same unmanaged conventions section as the
  reviewer record, documented in agent-setup's `references/audit.md`
  §forge-record, not in the canonical blocks or `docs/agent-workflow.md`.**
  Only agent-setup writes it, and the two consumers describe what they look
  for in their own text, so nothing in a managed block needs to point at it.
  Rejected: a pointer from the canonical `pull-requests` block, because that
  would resync every downstream project for a record most of them never
  need.
- **The audit offers to write the record; it isn't detect-only like the
  reviewer record.** A reviewer record is observation and must never be
  fabricated. The forge record derives mechanically from the remote path
  and the forge CLI's own answer, so the only thing to confirm is the
  unmanaged-content write. `ssh -G` is only a hint. It reports the SSH
  transport endpoint, so it echoes an unconfigured alias back with exit 0
  and names a transport-only host such as `ssh.github.com` under a port-443
  config. Neither is the forge host. `gh repo view --json url` is the authority,
  and the audit asks the user when `gh` cannot resolve the alias. That
  answer binds to the audited remote only when its `nameWithOwner` matches
  the derived slug, since a second remote or a `gh repo set-default` aims
  the argument-less form elsewhere, and only the base repository's remote
  may correct an existing record. Rejected: accepting any `ssh -G` hostname
  that merely differs from the alias. Writing it also made the forge record
  the first audit item that touches unmanaged content, which the detect-only
  reviewer record never did, so init settles it before its single AGENTS.md
  write and update mode lists it among the unmarked-content exceptions and
  protects it from a block refresh alongside the reviewer record.
- **Remote URLs are redacted where they are read, not just where they are
  written.** `git remote -v` and `git remote get-url` print an HTTP(S)
  URL's embedded credentials verbatim; a throwaway repo reproduced that.
  Recording the URL would commit a token, and printing it would leak the
  same token into the agent transcript, so the audit pipes both reads
  through a `sed` redaction that leaves host and path intact and reports
  only that a credential was present. Refute-first result: confirmed by
  that check, not disproved. The slug likewise comes from the base remote's
  fetch URL through `git remote get-url`, since a remote's separate push
  URL can name a fork.
- **The issue's premise that `gh` cannot map the alias was wrong for this
  alias, and the fix stands anyway.** `gh` normalizes any `*.github.com`
  host to `github.com`, so `gh repo view` resolves `bnw.github.com` remotes
  in this repo and in freeside. The failing sessions guessed the owner from
  sibling projects instead of asking `gh`. A record that states the slug
  stops the guessing, and it also covers aliases without that suffix, which
  `gh` cannot resolve at all. The reference says so, so a failed resolution
  isn't read as evidence against the record.
- **An existing record is validated on every run; only a new one waits for
  an aliased remote.** Both consumers prefer the record over the remote, so
  a transfer or a switch to a canonical URL would otherwise leave a stale
  record routing them while the alias-only trigger skipped the check.
  Rejected: keeping one trigger for both reading and writing the record.
- **free-skills carries its own record.** Its origin uses the same alias,
  so the dogfooded AGENTS.md gets the record the audit would write.

## Scope Left Open

self-merge and visual-evidence also take `--repo` and infer it from the
origin remote. The issue scoped the consumer change to await-pr-review and
merge-cleanup; extending it is a follow-up.

Revisit when a project uses a forge other than GitHub, since the record's
host field then carries the forge identity `gh` cannot supply.
