# Claim Rules for free-skills

Issue #417 carries the contract. The rules live in the Claiming section of
`AGENTS.md`. Issue #418 defines the same record shape for downstream projects
in agent-setup.

## Decisions

- **Chose to add claim rules now over waiting for a collision.** The owner
  decided this from a gap found by reading; no double start has been observed.
  `plan-and-handle-batch` §Occupied Issues falls back to "an open PR links the
  issue" when a project defines no claim rules, and a tracker keeps a unit
  startable until its PR merges. A second batch, or a separate "Handle #N"
  thread, would start any issue still being implemented.
- **Chose a label plus a marker comment over the Assignees field.** Agents
  run `gh` as the owner's account, so an assignee names the same person for
  every run and can't tell two runs apart. The comment names the run and
  carries the expiry. The label makes claimed issues easy to list, and only
  counts together with an unexpired comment.
- **Chose no draft PRs as a claim signal.** The owner rejected them.
- **Chose a 24-hour expiry over a shorter one.** An implementer can wait
  overnight for the owner's answer without losing its claim. A claim usually
  ends within hours, when the PR opens, so a dead claim blocks an issue for a
  day at most. The holder extends a claim by editing its own comment.
- **Chose the implementer as the only claimant over the planner or
  orchestrator.** `plan-work-unit` tells the planner not to claim, and the
  batch skill forbids its orchestrator to touch claims. Keeping one writer
  means the run that holds the claim is the run that releases it. This leaves
  the planning window uncovered: two overlapping batches can both plan one
  issue. Follow-up: #420.
- **Chose a reread over a lock.** Two agents can post claims at the same
  moment. Each rereads the issue, and the one with the newer comment deletes
  it and stops. The forge offers no atomic claim, and comment order is the
  only shared clock.
- **Added a rule for a replaced holder.** The contract says a stale claim may
  be replaced, but not what the old holder does on return. The agent chose:
  it stops, leaves the label, and reports the newer claim. Otherwise it could
  remove the label under the new holder and erase a live claim.
- **Chose to delete the claim comment on release over removing only the
  label.** The contract releases by removing the label. A pre-push review
  showed the gap: the comment stays unexpired, so the next assigned run passes
  the occupancy check, posts, and then loses the reread to a claim nobody
  holds. Deleting the comment closes it. The open PR, or the holder's report,
  keeps the record of who worked the issue.
- **Chose not to restrict who may post a claim comment.** The repository is
  public, so an outsider could post the marker and block an issue. The
  blocked agent reports the claim, and the owner deletes the comment. A
  write-access rule would add a check to every read for a nuisance nobody has
  seen.

Revisit when several people with their own accounts work the backlog (the
Assignees field could then tell holders apart), or when a claim expires under
a live run often enough to show 24 hours is too short.
